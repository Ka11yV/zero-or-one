# 게임 기획서 — Zero or One: Logic (논리 회로 퍼즐)

> 버전 0.1 · 2026-11-08
> 플랫폼: 웹 브라우저 (데스크톱 우선, 태블릿 대응) · 언어: 한국어 / English

---

## 1. 컨셉

**"NAND 게이트 하나로 시작해, 내 손으로 만든 부품만으로 컴퓨터를 완성한다."**

플레이어는 단 하나의 기본 부품(NAND)만 가진 채 시작한다. 각 레벨에서 주어진 명세(진리표 또는 동작 설명)를 만족하는 회로를 조립하면,
그 회로가 **새 칩(블랙박스 부품)** 으로 포장되어 툴박스에 추가된다. 이렇게 쌓아 올린 칩들로 가산기 → 레지스터 → **RAM** → ALU → **계산기** → **CPU/컴퓨터**에 도달한다.

### 설계 목표
1. **원리 이해가 보상이다** — 클리어마다 "왜 이렇게 되는가"를 설명하는 원리 카드를 얻는다.
2. **내가 만든 것만 쓴다** — 모든 상위 부품은 플레이어가 직접 만든 것. 컴퓨터를 완성했을 때 "전부 내가 만들었다"는 감각.
3. **실패가 학습이다** — 틀린 진리표 행, 잘못된 신호 흐름을 눈으로 보여줘 스스로 고치게 한다.
4. **추상화의 사다리** — 칩 내부를 열어볼 수 있지만 평소엔 블랙박스로 다룬다 (복잡도 관리 = 컴퓨터 공학의 핵심 사고).

### 대상
- 컴퓨터 구조에 호기심 있는 중고생~대학생, 개발자, 퍼즐 게이머
- 사전 지식 불필요 (2진수도 게임 안에서 배운다)

## 2. 핵심 게임 루프

```
[챕터 맵] → [브리핑] → [조립] ⇄ [실행/관찰] → [검증] → [원리 카드] → [칩 해금] → [챕터 맵]
                                   ↑                │ 실패
                                   └── [힌트] ←─────┘
```

| 단계 | 내용 |
|---|---|
| 브리핑 | 만들 부품 이름, **왜 필요한가**(한 문단), 입출력 핀, 목표 진리표/타이밍 |
| 조립 | 해금된 부품만 사용해 캔버스에 배치·배선 |
| 실행/관찰 | 입력 스위치를 직접 토글하며 신호 흐름 관찰 (선 색 = 0/1) |
| 검증 | "테스트" 버튼 → 모든 테스트 벡터 자동 실행. 틀린 행을 진리표에서 빨간색으로 강조 |
| 원리 카드 | 불 대수식, 동작 원리, "컴퓨터 속 어디에 쓰이나", 재미있는 사실 |
| 칩 해금 | 완성 회로가 칩으로 포장되어 툴박스에 추가. 아이콘/이름은 레벨이 지정 |

## 3. 캠페인 구조

총 **9개 챕터, 약 50개 레벨**. 각 챕터 끝에는 **보스 레벨**(챕터 부품을 조합한 의미 있는 결과물)이 있다.

### 의존 관계 개요
```
NAND ─▶ NOT ─▶ AND/OR ─▶ XOR ─▶ MUX/DEMUX/디코더 ─▶ 반가산기 ─▶ 전가산기 ─▶ N비트 가산기
                                     │                                         │
                                     ▼                                         ▼
                                SR 래치 ─▶ D 래치 ─▶ D 플립플롭 ─▶ 레지스터 ─▶ RAM      ALU ─▶ 계산기
                                                                      │          │        │
                                                                      └──────────┴────────┴─▶ CPU ─▶ 컴퓨터
```

### 챕터 0 · 첫 전류 (튜토리얼)
| ID | 레벨 | 목표 | 배우는 것 |
|---|---|---|---|
| 0-1 | 불 켜기 | 스위치 → 전구 연결 | 배치, 배선, 신호 0/1 (선 색) |
| 0-2 | 나눠 주기 | 스위치 1개 → 전구 2개 | 선 분기(팬아웃) |
| 0-3 | 첫 부품 NAND | NAND의 진리표를 직접 토글하며 채우기 | 진리표 읽는 법, NAND 소개 |

**원리 카드 0-3:** "NAND = NOT AND. 둘 다 1일 때만 0. 이 하나로 모든 디지털 회로를 만들 수 있다."

---

### 챕터 1 · 하나로 모든 것을 (기본 게이트)
허용 부품: NAND (+ 클리어한 게이트)

| ID | 만들 칩 | 목표 진리표 | 힌트 ①→②→③ | 원리 카드 요지 |
|---|---|---|---|---|
| 1-1 | **NOT** | A=0→1, A=1→0 | ① NAND의 두 입력이 같으면? ② 입력을 묶어라 ③ A를 NAND 양쪽에 | NAND(A,A)=¬A |
| 1-2 | **AND** | 11→1, 그 외 0 | ① NAND는 AND의 반대 ② 뒤집으면? ③ NAND→NOT | AND = ¬NAND |
| 1-3 | **OR** | 00→0, 그 외 1 | ① 드모르간 ② ¬A NAND ¬B ③ 입력 각각 NOT 후 NAND | A∨B = ¬(¬A∧¬B) (드모르간) |
| 1-4 | **NOR** | 00→1, 그 외 0 | ① OR의 반대 | NOR도 만능 게이트 |
| 1-5 | **XOR** | 01,10→1 | ① "다를 때만 1" ② (A∨B)∧¬(A∧B) ③ NAND 4개 해법도 존재 | 덧셈의 1의 자리 = XOR |
| 1-6 | **XNOR** | 00,11→1 | ① XOR의 반대 | 같음 비교기 |
| 1-B | **보스: 다수결 투표기** | 3입력 중 2개 이상 1이면 1 | ① AB∨BC∨CA | 조합 논리 설계 = 진리표 → 식 → 회로 |

**별점 기준(선택):** XOR NAND 4개, NOT 1개 등 최소 개수 달성 시 ★★★

---

### 챕터 2 · 선택과 분배 (조합 회로)
| ID | 만들 칩 | 명세 | 원리 카드 요지 |
|---|---|---|---|
| 2-1 | **MUX 2:1** | S=0→A, S=1→B | "선택 신호가 데이터 길을 고른다" — CPU가 연산 결과를 고르는 원리 |
| 2-2 | **DEMUX 1:2** | 입력을 S에 따라 Y0/Y1로 | 한 신호를 목적지로 보내기 |
| 2-3 | **MUX 4:1** | S1S0로 4개 중 선택 | MUX를 트리로 쌓는 계층 설계 |
| 2-4 | **디코더 2→4** | 2비트 → 4비트 원-핫 버스 y | **주소 해석의 기초** (RAM에서 재등장) |
| 2-5 | **디코더 3→8** | 3비트 → 8비트 원-핫 버스 | 작은 디코더 + 최상위 비트 허가로 확장 |
| 2-6 | **인코더 4→2** | 켜진 줄 번호를 2진수로 | 키패드 입력 → 숫자 |
| 2-B | **보스: 신호등 제어기** | 2비트 상태 → 빨강/노랑/초록 램프 | 디코더 해법 → 논리 최소화(★★★) |

---

### 챕터 3 · 1+1=10 (2진 산술)
시작 시 **2진수 미니 강의** 카드: 자리값, 2진↔10진 변환 퀴즈(게임 내 인터랙티브).

| ID | 만들 칩 | 명세 | 원리 카드 요지 |
|---|---|---|---|
| 3-1 | **반가산기** | S=A⊕B, C=A∧B | 1+1=10: 합은 XOR, 올림은 AND |
| 3-2 | **전가산기** | A+B+Cin → S, Cout | 아랫자리 올림까지 더하기 |
| 3-3 | **4비트 가산기** | 전가산기 4개 연결 | 리플 캐리 — 올림이 물결처럼 전파(지연 시각화) |
| 3-4 | **2의 보수기** | -X = ¬X + 1 | 음수를 덧셈기로 다루는 트릭 |
| 3-5 | **4비트 감산기** | A-B = A + ¬B + 1 | 가산기 재사용, Cin=1의 의미 |
| 3-6 | **4비트 비교기** | A=B, A<B 출력 | 뺄셈 결과로 비교 (플래그의 기원) |
| 3-B | **보스: 오버플로 감지기** | 부호 있는 4비트 덧셈 → sum, ovf | 올림(C)과 오버플로(V)의 차이 |

---

### 챕터 4 · 버스를 타고 (다비트)
새 내장 부품: **버스 분리기 / 버스 합치기**(배선 편의 도구), **8비트 스위치·8비트 표시기**(10/2/16진 전환)

| ID | 만들 칩 | 명세 |
|---|---|---|
| 4-1~4 | **NOT8 / AND8 / OR8 / XOR8** (레벨 4개) | 비트별 연산 (버스 사용법, 마스킹, 조건부 반전) |
| 4-5 | **8비트 MUX 2:1 (MUX8)** | 제어 신호 하나를 8비트에 팬아웃 |
| 4-6 | **8비트 가산기 (ADD8)** | 4비트 가산기 2개 (표본 테스트 48줄) |
| 4-7 | **8비트 MUX 4:1 (MUX4_8)** | 같은 설계, 다른 폭 |
| 4-8 | **디코더 4→16 (DEC4)** | 행/열 격자 디코딩 (DEC2 ×2 + AND 16) |
| 4-B | **보스: 8비트 덧셈/뺄셈기 (ADDSUB8)** | SUB 신호 1개로 모드 전환 (XOR로 조건부 반전) |

**원리 카드:** "워드(word)란? 컴퓨터가 한 번에 다루는 비트 묶음. 8비트 = 0~255 / -128~127."

### 챕터 5 · 기억하는 회로 (순차 회로)
새 개념: **시간**. 테스트가 진리표 대신 **순서(시퀀스)** 로 바뀌고, 패널에 **클럭 버튼(한 번 / 자동)** 과 **타이밍 차트** 가 나타난다. 클럭은 별도 부품이 아니라 레벨의 입력 핀 `clk` 이다.

| ID | 만들 칩 | 명세(시퀀스 테스트) | 원리 카드 요지 |
|---|---|---|---|
| 5-1 | **SR 래치** | S=1→Q=1 유지, R=1→Q=0 유지 | 교차 결합 = 1비트 기억 (NOT 고리 발진 실험은 원리 카드에서 안내) |
| 5-2 | **D 래치** | E=1일 때 Q=D, E=0이면 유지 | "언제 저장할지" 제어 |
| 5-3 | **D 플립플롭** | 클럭 상승 엣지에만 저장 | 마스터-슬레이브: 순간 포착 |
| 5-4 | **1비트 레지스터** | LOAD=1이면 다음 클럭에 저장 | MUX + DFF: 선택적 저장 |
| 5-5 | **8비트 레지스터** | 1비트 ×8 | 레지스터 = CPU의 작업대 |
| 5-6 | **4비트 카운터** | 클럭마다 +1, RESET | 레지스터 + 가산기 피드백 (PC의 원형) |
| 5-B | **보스: 스톱워치** | run/reset/clk → q[4] (run=0이면 정지) | 제어 신호가 동작을 바꾼다 (cin = run) |

### 챕터 6 · 주소로 기억하기 (**RAM**)
| ID | 만들 칩 | 명세 | 원리 카드 요지 |
|---|---|---|---|
| 6-1 | **RAM 4×8** (4워드) | ADDR(2)·DATA_IN(8)·WRITE·CLK → DATA_OUT(8) | 디코더로 고르고 → 레지스터에 쓰고 → MUX로 읽는다 |
| 6-2 | **RAM 16×8** | ADDR 4비트 | 같은 구조를 키우기 (디코더 4→16) |
| 6-3 | **RAM 256×8** | ADDR 8비트 | RAM 16×8 ×16 + 상위 4비트 디코딩(디코더 4→16) + 읽기용 8비트 MUX 16:1(4:1 ×5 트리) — 계층적 주소 |
| 6-B | **보스: 녹음기** | COUNTER4가 주소를 만들고 RAM16에 기록·재생 (rec/reset/clk) | 주소 계산 + 메모리 = 명령어 인출(fetch)의 예고 |

> 6-2부터 플레이어가 검증한 RAM 칩(RAM4/16/256)은 **기능 모델(빠른 모드)**로 시뮬레이션되고, 패널의 **메모리 뷰어**가 내용을 주소 순서대로 보여준다. → TECH_DESIGN §5.3

### 챕터 7 · 계산하는 기계 (ALU · **계산기**)
새 I/O 장치(패널): **7세그먼트 표시기**(폭 7 출력, 비트 0 = a … 6 = g), **키패드**(0–9, + = 10, − = 11, = = 12 → key 핀에 값 + clk 펄스). 샌드박스에서도 폭 7 출력은 7세그먼트로 표시.

| ID | 만들 칩 | 명세 | 원리 카드 요지 |
|---|---|---|---|
| 7-1 | **ALU** | a·b(8), op(2): 0 ADD, 1 SUB, 2 AND, 3 OR → out(8) | 모든 연산을 다 계산하고 MUX로 고른다 |
| 7-2 | **ALU8** (플래그) | op(3): ADD/SUB/AND/OR/XOR/NOT a/a/b → out, z, n, c (c는 ADD/SUB만) | 플래그 = 다음 판단의 근거 |
| 7-3 | **SEG7** | in(4) → seg(7), 0–9·A–F | 진리표 → 회로 (DEC4 + OR 묶기) |
| 7-4 | **BCD8** (0–99) | in(8) → tens(4), ones(4) | 더블 대블: 5 이상이면 +3 후 밀기 |
| 7-B | **보스: 계산기** | key(4)·clk → tens(7)·ones(7). 한 자리 수 a ± b, 결과 0–18 | 상태 기계 = 레지스터(상태) + 제어(load) |

---

### 챕터 8 · 스스로 일하는 기계 (**컴퓨터**)
목표 CPU: **8비트 누산기 구조**, RAM256 공유(폰 노이만), 2바이트 명령어. 명령어 집합·제어 신호는 TECH_DESIGN §7.

| ID | 종류 | 만들 것 | 명세 | 원리 카드 요지 |
|---|---|---|---|---|
| 8-1 | 회로 | **PC** | d(8), inc, load, reset, clk → q(8). 우선순위 reset > load > inc | "다음에 읽을 명령의 주소" |
| 8-2 | 회로 | **BRANCH** | op(4), z, n, c → take (JMP / JZ·z / JC·c / JN·n) | if문 = 플래그 + AND |
| 8-3 | 회로 | **STEP** | t_rst, hold, reset, clk → t(3): 0→4 순환 | 명령을 시간으로 쪼갠다 |
| 8-4 | 회로 | **CONTROL** | op(4), t(3), take → 제어선 12개 (t = 0–4 진리표 160행) | 명령어 = 제어 신호의 묶음 |
| 8-5 | 회로 | **CPU** | run, pa, pd, pw, in, reset, clk → out, ow, halt, pc, a | 저장된 프로그램, fetch-decode-execute |
| 8-6 | 프로그램 | 덧셈 | [0x80] + [0x81] → OUT (★ 8바이트) | 기계어와 어셈블리어 |
| 8-7 | 프로그램 | 카운트다운 | 10…0 OUT (★ 13바이트) | 반복 = 뒤로 점프 + 조건 |
| 8-8 | 프로그램 | 곱셈 | [0x80] × [0x81] → OUT (★ 27바이트) | 소프트웨어가 하드웨어를 넓힌다 |
| 8-B | 프로그램 | **최종 보스: 내 컴퓨터** | IN n → OUT 1+…+n (★ 33바이트) | NAND에서 컴퓨터까지 (엔딩) |

**프로그램 레벨 화면**: 왼쪽 어셈블리 편집기(줄마다 주소 표시, 오류 줄 표시, 명령어 표) · 가운데 *플레이어가 만든 CPU 칩*을 그대로 시뮬레이션(PC/A/지금 명령/클럭/HALT, OUT 7세그먼트 3자리, IN 키패드, RAM 256바이트 보기) · 오른쪽 브리핑/테스트/힌트. 테스트는 경우마다 프로그램(+데이터)을 적재해 HALT까지 실행하고 OUT 순서를 비교. 별점은 프로그램 크기(바이트).

**엔딩:** 8-B 클리어 시 "여러분의 CPU는 NAND N개" (플레이어 CPU 칩의 실제 NAND 수) + 칩 계층 한 줄.

## 4. 학습 설계 (원리 이해 장치)

| 장치 | 설명 | 노리는 이해 |
|---|---|---|
| 신호 색 | 0 = 어두운 회색, 1 = 밝은 색. 버스는 값 라벨 | 신호 흐름 직관 |
| 실시간 진리표 | 현재 회로의 진리표 vs 목표 진리표, 틀린 행 강조 | 명세 ↔ 구현 대조 |
| 단계 실행 | 게이트 1단계 / 클럭 1틱 단위 진행, 타이밍 차트 | 지연, 피드백, 엣지 트리거 |
| 힌트 3단계 | ① 개념 질문 ② 부분 구조 ③ 거의 정답. 벌점 없음, 사용 기록만 | 스스로 생각할 기회 우선 |
| 원리 카드 | 불 대수식 + 동작 설명 + 쓰임새 + 재미있는 사실 | "왜"에 대한 답 |
| 도감 | 획득한 원리 카드 모음, 언제든 재열람 | 복습 |
| 칩 열어보기 | 칩 더블클릭 → 내부 회로 (읽기 전용) | 계층/추상화 |
| 미니 퀴즈 | 챕터 시작 시 개념 퀴즈 1~3개 (2진수, 2의 보수 등) | 선행 개념 |
| 별점 도전 | 최소 NAND 수 / 최소 지연 깊이 | 최적화 사고 (선택) |

**톤:** 설명은 짧게, 먼저 해보게 하고 나중에 설명한다("발견 → 정리" 순서).

## 5. UI / UX

```
┌───────────────────────────────────────────────────────────────────┐
│ ◀ 맵 | 1-5 XOR  | ▶실행 ⏸ ⏭단계  속도[──●─] | ↶ ↷ | 🔍 | KO/EN │
├──────────┬────────────────────────────────────────┬───────────────┤
│ 툴박스   │                                        │ [브리핑]      │
│ ▸ NAND   │            캔버스 (그리드)             │ [진리표]      │
│ ▸ NOT    │      입력핀 ●──▷NAND──●── 출력핀       │ [테스트 결과] │
│ ▸ AND    │                                        │ [힌트]        │
│ ...      │                                        │               │
│          │                                        │  [ 테스트 ▶ ] │
└──────────┴────────────────────────────────────────┴───────────────┘
```

- **조작:** 툴박스에서 드래그 배치 / 핀→핀 드래그로 배선 / 선 클릭 후 Delete / 휠 줌 / 스페이스+드래그 팬 / Ctrl+Z·Y / 박스 선택·복사·붙여넣기 / R 회전
- **챕터 맵:** 노드형 진행 맵, 잠금·해금·별점 표시
- **샌드박스:** 해금된 모든 칩으로 자유 제작, 저장 슬롯, JSON 내보내기/가져오기, 커스텀 칩 만들기
- **접근성:** 색만으로 0/1 구분하지 않음(선 굵기·패턴 병행), 색약 팔레트 옵션, 키보드 조작
- **언어:** 상단 KO/EN 토글, 즉시 전환, 설정 저장

## 6. 진행 / 저장
- 진행도(클리어·별점·힌트 사용), 각 레벨의 마지막 회로, 해금 칩 → `localStorage`
- 플레이어가 만든 칩은 **실제 회로 그대로 저장**되어 이후 레벨에서 사용 (재설계하면 상위 칩에 반영)
- 설정: 언어, 색 팔레트, 시뮬레이션 속도
